## 1. Layout & runtime

- `apps/api`: FastAPI `/api/v1`, SQLAlchemy models/services, Alembic, pytest; `apps/api/app/main.py#app`, `apps/api/app/api/v1/router.py#api_router`.
- `apps/admin-web`: staff React/Vite application, permission-guarded routes; `apps/admin-web/src/app/router.tsx#router`.
- `apps/store-web`: customer React/Vite application, public/account/approved-business routes; `apps/store-web/src/main.tsx#App`.
- `apps/mobile`: existing native/web customer client; shared store API with platform token storage; `apps/mobile/src/api.ts#api`.
- Notifications service reuses the API image/code, not a separate app folder; worker `apps/api/app/notify.py#main`, Compose `docker-compose.prod.yml#notifications`.
- `packages/api-client` customer HTTP/contracts; `packages/core` commerce/validation/translations; `packages/shared` generated API types; `packages/ui-web` Button; `packages/design-tokens` tokens; exports in section 5.
- Production: browser → frontend nginx `/api/` → `api:8000` → `postgres:5432`; PostgreSQL host binding `127.0.0.1:5433`; `docker-compose.prod.yml#services`, `apps/admin-web/nginx.conf#api_upstream`, `apps/store-web/nginx.conf#api_upstream`.
- Local API launcher uses root `.venv`, port 8000; `scripts/dev-api.sh#ROOT_DIR`. Root commands/workspaces: `package.json#scripts`, `pnpm-workspace.yaml#packages`.
- Backend env/config: `apps/api/app/core/config.py#Settings` loads `.env`/`../../.env`; production validation, pool, upload, provider and cache flags live here. Never copy secret values into context.
- Browser API URL/timeout: `apps/admin-web/src/lib/api-client.ts#apiClient`, `apps/admin-web/src/lib/http-policy.ts#apiTimeoutMs`, `apps/store-web/src/lib/api.ts#api`; mobile env: `apps/mobile/src/api.ts#apiUrl`.
- `scripts` owns dev launchers/API export; `docs` owns operational/build guides: [Deployment](DEPLOYMENT.md), [Operations runbook](OPERATIONS_RUNBOOK.md). Link these; do not duplicate deployment instructions.

## 4. Main flows

- Paths below include `/api/v1`; query keys are client-local. Successful admin mutations also invalidate dashboard-summary via `apps/admin-web/src/lib/query-client.ts#queryClient`; mapped admin actions append audit rows via `apps/api/app/services/audit_service.py#audit_request`.

**Admin login / restore / expiry**

- `apps/admin-web/src/features/auth/login-page.tsx#LoginPage` → `apps/admin-web/src/features/auth/auth-store.ts#useAuthStore` → `apps/admin-web/src/features/auth/auth-client.ts#authClient` → POST /api/v1/auth/login → `apps/api/app/api/v1/routes/auth.py#login` → credential/identity checks → admin_users.last_login_at + audit_logs → tokens/user stored, workspace shown.
- Restore: `apps/admin-web/src/features/auth/auth-store.ts#useAuthStore` → access token present: GET /api/v1/auth/me; absent: POST /api/v1/auth/refresh then me → `apps/api/app/api/v1/routes/auth.py#refresh`, `apps/api/app/api/v1/routes/auth.py#me` → `apps/api/app/core/deps.py#admin_user_with_permissions_query` → reads only → cached shell while restoring; invalid refresh clears user/queries and routes login, transient failure retains session.
- Concurrent 401 → `apps/admin-web/src/lib/api-client.ts#apiClient` → `apps/admin-web/src/features/auth/auth-store.ts#refreshAccessToken` single-flight → one authenticated replay; no roles/warehouses prerequisite for restore.

**Staff notification inbox**

- Top-bar `apps/admin-web/src/features/notifications/notification-bell.tsx#NotificationBell` → `apps/admin-web/src/features/notifications/notifications-api.ts#getNotifications` → GET /api/v1/notifications → `apps/api/app/api/v1/routes/admin_notifications.py#list_admin_notifications` → `apps/api/app/services/admin_notification_service.py#notification_feed` → reads only → [admin-notifications,userId,sortedPermissions], 30-second foreground poll, keyset pagination.
- Successful open → `apps/admin-web/src/features/notifications/notifications-api.ts#markNotificationsOpened` → POST /api/v1/notifications/opened → `apps/api/app/api/v1/routes/admin_notifications.py#open_admin_notifications` → `apps/api/app/services/admin_notification_service.py#mark_opened` → admin_notification_states → refetch personal feed/count; click navigates entity, payment/delivery anchors or inventory warehouse+SKU filters.

**Admin create order**

- `apps/admin-web/src/features/orders/create-order-drawer.tsx#CreateOrderDrawer` → `apps/admin-web/src/features/orders/orders-api.ts#previewOrder` → POST /api/v1/orders/preview → `apps/api/app/api/v1/routes/orders.py#preview_order` → `apps/api/app/services/order_service.py#preview_order` → no writes → preview totals.
- Save → `apps/admin-web/src/features/orders/orders-api.ts#createOrder` → POST /api/v1/orders → `apps/api/app/api/v1/routes/orders.py#create_order` → `apps/api/app/services/order_service.py#create_order` → orders/order_items/order_status_history (+ notification hook) → invalidate [orders], navigate /orders/:id; PENDING, no allocation yet.

## 6. How to add things

**API endpoint**

1. Find existing handler/service and callers; follow `apps/api/app/api/v1/routes/products.py#create_product`, `apps/api/app/services/catalog_service.py#create_product`.
2. Define/extend request/response schema, e.g. `apps/api/app/schemas/catalog.py#ProductCreate`; preserve detail/code errors with `apps/api/app/core/errors.py#AppError`.
3. Wire session + permission dependencies; mount new router in `apps/api/app/api/v1/router.py#api_router`; customer endpoints use `apps/api/app/core/store_deps.py#require_verified_customer` where applicable.
4. Add mutation audit mapping if appropriate: `apps/api/app/services/audit_service.py#AUDITED_ENDPOINTS`; use service transactions, not GET side effects.
5. Add isolated API/service coverage following `apps/api/tests/conftest.py#api_client`; regenerate contracts via `package.json#scripts` generate:api; extend existing feature client/query keys.

**DB column/table + migration**

1. Extend model using `apps/api/app/core/database.py#Base` and mixins in section 5; register new model exports in `apps/api/app/models/__init__.py`.
2. Add Alembic revision under `apps/api/alembic/versions`; `apps/api/alembic/env.py#target_metadata` reads registered models; follow explicit upgrade/downgrade style in `apps/api/alembic/versions/data_controls_0001_primary_warehouse.py#upgrade`.
3. Review constraints/defaults/backfill and upgrade/downgrade SQL; model edits alone do not update an existing database.
4. Update schema/service/client contracts and run tests on throwaway local *_test DB; `apps/api/tests/conftest.py#test_session_factory` recreates metadata, so it does not validate migration rollout.
5. Take a backup before schema-changing operations; follow [Deployment](DEPLOYMENT.md). Production does not auto-migrate: deploy needs `alembic upgrade head`; `apps/api/docker-entrypoint.sh#KABISA_RUN_MIGRATIONS`.

**Permission**

1. Add code to `apps/api/app/seed/catalogue.py#PERMISSION_CODES_BY_GROUP`; update `apps/api/app/seed/catalogue.py#ROLE_PERMISSION_CODES` deliberately.
2. Update catalogue expected counts/validation and `apps/api/tests/test_permission_catalogue.py#test_permission_catalogue_and_role_mappings_are_complete`.
3. Enforce backend through `apps/api/app/core/deps.py#require_permission`; add allowed/denied-role coverage, as in `apps/api/tests/test_payment_delivery_gate.py#test_payment_api_delivery_gate_and_finance_permissions`.
4. Gate UI route/control through `apps/admin-web/src/features/auth/permission-guard.tsx#PermissionGuard`, `apps/admin-web/src/features/auth/auth-store.ts#useHasPermission`; edit `apps/admin-web/src/lib/navigation.ts#navigation` if needed.
5. Plan explicit synchronization of existing permission/role rows; source catalogue changes do not themselves change deployed rows. Do not casually run bootstrap/seed; document deployment action and update section 2.

**Admin page / route / navigation**

1. Extend the relevant feature client/component; inspect `apps/admin-web/src/features/orders/orders-page.tsx#OrdersPage` and section 5 first.

## 7. Known duplicates and issues

- Parallel HTTP policies: admin Axios `apps/admin-web/src/lib/api-client.ts#apiClient` vs customer fetch `packages/api-client/src/index.ts#createApiClient`; use the appropriate existing client, do not introduce a third.
- Parallel error UI: `apps/admin-web/src/components/ui/resource-state.tsx#ErrorState` vs `apps/store-web/src/components/ui.tsx#ErrorState`; fixes need both clients checked.
- Money formatting differs: admin zero fraction digits `apps/admin-web/src/lib/utils.ts#formatMoney` vs core up to two `packages/core/src/index.ts#formatMoney`; do not silently unify behavior.
- Handwritten status/contracts overlap generated types: `apps/admin-web/src/features/orders/orders.data.ts#OrderStatus`, `packages/api-client/src/index.ts#StoreOrder`, `packages/shared/src/index.ts#ApiListResponse`; backend `apps/api/app/models/order.py#OrderStatus` remains authority.

- Credit limit is stored/displayed, not an order approval/checkout gate: `apps/api/app/services/customer_service.py#update_customer`, `apps/api/app/services/order_service.py#_quote`, `apps/api/app/services/store_commerce_service.py#checkout_quote`; no enforcement should be assumed.
